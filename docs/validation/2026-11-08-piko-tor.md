## VPN behavior and remaining limits

Android permits one active VPN per profile. The 0.2 source retains
the visible-VPN guard and post-consent checks; their regression unit tests passed
in the current run. Before requesting consent,
the companion checks for another VPN visible to its UID and refuses to proceed if one
is found. **This is a best-effort guard:** Android can hide per-app VPNs that exclude
the companion. The user must inspect Android's VPN settings before starting; the
guard does not guarantee detection or preservation of every other VPN provider.

After the consent dialog, the companion rechecks its permission and selected target
before starting. If another provider was selected in the meantime, a stale success
result does not trigger a new consent request or start the service. Revocation
invalidates callbacks before queued main-thread cleanup can release resources.
Unit tests cover these code paths; real provider-switching and OEM behavior still
require device validation.

The **older 3.9.0-tor.2 companion lacks the visible-VPN guard and post-consent
recheck** included in 0.2.

The new default does not require **Always-on VPN** or **Block connections without
VPN**. It routes only X while ON and deliberately closes the tunnel for direct X
connectivity when OFF. Retained-TUN engine failure must still block affected X
traffic. Unexpected tunnel loss can expose direct connectivity without the optional
system barrier. Advanced users may choose lockdown, accepting its impact on other
apps and OFF behavior; the companion never enables it automatically. No current
result certifies exhaustive prevention of DNS, IPv4/IPv6, UDP/QUIC, WebView, native
or isolated-process leaks.

Not demonstrated by this session: exhaustive physical-device network coverage of
X and the companion; a fresh account login; full media, direct-message and
notification behavior; reboot/early-boot traffic; Wi-Fi/mobile transitions; background/battery
restrictions; longer automatic-restart observation; and exhaustive negative tests
for other engine failures, service death and policy/provider changes.

The [October 19 observations](../../companion/README.md#historical-android-runtime-checks-2026-10-19)
remain historical evidence for revision `4602d80a`. They include unsuccessful
automatic recovery after process death and an unattributed physical DNS exchange.
They neither certify this development version nor resolve those earlier limits.

maintained on `main`; Morphe's **Use pre-release** toggle therefore stays off.

The bundle requires companion version code 2 or later and opens the installation
guide when it is missing or outdated. The older `v3.9.0-tor.2`/0.1 release requires
system lockdown and lacks the new ON/OFF default. Its public companion also uses
a different signing certificate; follow the [migration instructions](../../companion/README.md#signing-and-migration)
rather than uninstalling X or clearing its data.
